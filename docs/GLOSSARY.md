# Glossary — Project Site Tracker

Domain and technical terms used in the code, the UI and the rest of this
documentation. Definitions describe this system, not the general industry.

* Data model: [`ERD.md`](./ERD.md), [`SCHEMA.md`](./SCHEMA.md)
* Access rules: [`ACCESS-CONTROL.md`](./ACCESS-CONTROL.md)
* Design rationale: [`DECISIONS.md`](./DECISIONS.md)

---

## A

**Active flag (`active`)**
Boolean on master-data rows. `true` means in use; `false` means archived. Nothing
is hard-deleted. Appears on `Company`, `Project`, `Plaza`, `Department`, `Office`,
`TaskCategory` and `User` (where it means "can sign in", not archived).

**Actor**
The signed-in user performing an action. Activity and audit rows store
`actorId`. See `TaskActivity.actorId`, `AuditLog.actorId`.

**Admin**
A user with `User.isAdmin = true`. Global access to every company, project,
plaza, task, user, department and audit row. One of the four derived roles.

**ADR**
Architecture Decision Record. A short, numbered note explaining a decision and
its consequences. See [`DECISIONS.md`](./DECISIONS.md).

**Assignment ceiling**
The rule set in `canAssignTo` that decides who may assign whom, at which scope.
Admins and Head Office may assign any active user; project and site managers have
narrower ceilings. See [`ACCESS-CONTROL.md` §4](./ACCESS-CONTROL.md#4-assignment-ceiling).

**Audit trail**
Two separate append-only histories: `TaskActivity` for task work and `AuditLog`
for master-data changes. Neither has an edit or delete endpoint.

**AuditLog**
Table of master-data mutations with `entity`, `entityId`, `action`,
`before`/`after` JSON and `actorId`. Written inside the same transaction as the
change. Read via `GET /api/audit`. See [`SCHEMA.md`](./SCHEMA.md#auditlog).

---

## C

**Check constraint**
A database rule that restricts column values. This schema uses
`Task_scope_kind_check` to enforce the `Task.scope` / location-column
combinations. See [`SCHEMA.md`](./SCHEMA.md#constraints).

**Company**
Top of the delivery hierarchy. Three exist: **NHIT Eastern Projects Private
Limited** (`NEPPL`), **NHIT Southern Projects Private Limited** (`NSPPL`) and
**NHIT Western Projects Private Limited** (`NWPPL`). A company owns projects.

**Cuid**
Collision-resistant id generated by Prisma for ordinary rows (tasks, users,
activities, attachments). Catalogue rows use stable slugs instead.

---

## D

**Department**
A Head Office function such as Finance, Operations or IT. Stored in
`Department` with a stable slug id (`dept_fin`), a `code`, a `sortOrder` and an
`active` flag. Departments are **display metadata and a task location**, never a
permission boundary.

**Department task**
A task with `scope = DEPARTMENT` and `departmentId` set. Created and visible
globally to Admin/Head Office; invisible to project users unless assigned.

**Display role**
The role shown in the header: `ADMIN`, `HEAD_OFFICE` or `PROJECT_MANAGER`.
Derived from `isAdmin` and Head Office memberships, not stored. Site managers
display as `PROJECT_MANAGER`; the badge shows their plaza job titles instead.

---

## E

**ERD**
Entity–Relationship Diagram. The picture of tables and foreign keys. See
[`ERD.md`](./ERD.md).

---

## H

**Head Office (HO)**
The central functions that work across all three companies. A person becomes HO
by holding any `HeadOfficeMembership`. HO is **global**: membership is not scoped
to a company or project.

**Head Office-level task**
A task with `scope = HEAD_OFFICE` and no project, plaza or department. Created
only by Admin/HO. Part of the "Head Office" filter alongside department tasks.

**HeadOfficeMembership**
Join row between `User` and `Department`, with `isPrimary` and `assignedById`.
Exactly one primary per member is maintained by the API and a partial unique
index. Grants the global Head Office role.

---

## I

**IST (Indian Standard Time)**
`Asia/Kolkata`, UTC+05:30. The business day for due dates and overdue
calculations. `lib/dates.ts` converts "today in IST" to UTC midnight because
`Task.dueDate` is a `date` column.

---

## J

**JWT session**
Auth.js session strategy. The signed cookie carries the user id and `isAdmin`;
authorisation still re-reads the database on every request.

---

## M

**Master data**
Reference and configuration rows: companies, projects, plazas, departments,
offices, categories, users, memberships and assignments. Changes are recorded in
`AuditLog`.

**Migration**
A versioned SQL change under `prisma/migrations/`. Forward-only; applied
migrations are never edited. `prisma migrate deploy` runs them in production.

---

## O

**Office**
A Head Office city/office (`Office`, e.g. Delhi). Linked to users and used for
the assignee context label ("Head Office · Delhi"). Not a permission boundary.

**Overdue**
A task whose `dueDate` is strictly before today in IST and whose status is not
`COMPLETED`. Computed by `lib/dates.ts#isOverdue` and by list/stat queries.

---

## P

**PIU**
Project Implementation Unit. A free-text project metadata field
(`Project.piu`) describing the unit responsible for the project. The repo does
not define its internal structure.

**Plaza**
A toll plaza or corridor site inside a project. The unit where most field work
happens. `Plaza` stores `name`, `lengthKm`, `active` and `projectId`; location
metadata (`state`, `piu`, `ro`) lives on the project.

**Plaza-level task**
A task with `scope = PLAZA`, both `projectId` and `plazaId` set.

**PlazaAssignment**
Join row between `User` and `Plaza` with a `role` of `TOLL`, `MAINTENANCE` or
`CORRIDOR`, plus `isPrimary` and `assignedById`. Grants site-manager access to
that plaza.

**Primary (assignment)**
A display/ordering preference, not an extra permission. One primary Head Office
department per member; one primary plaza/project assignment per user where the UI
sets it.

**Prisma**
The ORM and migration tool. `lib/db.ts` exports a singleton `PrismaClient`;
`prisma/schema.prisma` is the schema source of truth.

**Project**
A road/stretch package owned by a company, with `round`, `state`, `lengthKm`,
`piu`, `ro` and `active`. Projects contain plazas and tasks. `Project.lengthKm`
is currently retained but unused by the UI.

**Project-level task**
A task with `scope = PROJECT`, `projectId` set and `plazaId` null. Visible to
everyone on the project; may be assigned to a site manager, who then sees it via
the assignee override.

**Project Manager (PM)**
A user with a `ProjectAssignment` on a project. Sees every task in that project,
including all plaza tasks, and may create tasks at project or plaza level. Also a
display role label.

**ProjectAssignment**
Join row between `User` and `Project`, with `isPrimary` and `assignedById`.
Grants project-manager access.

---

## R

**Reopen request**
A `TaskReopenRequest` asking to move a `COMPLETED` task back to `IN_PROGRESS`.
Created by a project or site manager with a reason; approved or rejected by
Admin/HO. At most one `PENDING` request per task.

**RO**
Regional Office. A free-text project metadata field (`Project.ro`). The repo
does not define its internal structure.

**Round**
The project's round: `ROUND_1` … `ROUND_4`. Used for grouping and dashboard
roll-ups.

---

## S

**Scope**
Where a task lives. `Task.scope` is one of `PROJECT`, `PLAZA`, `DEPARTMENT` or
`HEAD_OFFICE`, backed by a CHECK constraint. The client-side contract is in
`lib/task-scope.ts`; scope keys are `project:<id>`, `plaza:<id>`,
`department:<id>` and `head-office`.

**Seed**
`prisma/seed.ts`. Creates the demo catalogue, users, assignments, tasks,
activities and one pending reopen. Idempotent by upsert, but `SEED_RESET=1`
wipes first. Never run with real data.

**SessionUser**
The server-side identity object from `getSessionUser`: `id`, `role`, `isAdmin`,
`departmentName`, `officeName`. Not the JWT payload.

**Site Manager**
A user holding a `PlazaAssignment`. Sees tasks on their plazas plus tasks
assigned to them; may create tasks only on their own plazas. Displays as
`PROJECT_MANAGER` with a plaza job title.

**Slug id**
A stable, human-readable id for catalogue rows, e.g. `company_neppl`, `dept_fin`,
`office_delhi`, `cat_toll_operations`. Makes every environment identical.

**Soft archive**
Retiring a row with `active = false` instead of deleting it. Unique names/codes
stay reserved. Users are deactivated rather than archived.

---

## T

**Task**
The unit of work. One assignee, one scope, one status, optional category and due
date. Tasks are never deleted; they are completed and reopened through the
request workflow.

**TaskActivity**
Append-only task history: `CREATED`, `COMMENT`, `ASSIGNED`, `STATUS_CHANGED`,
`REOPEN_REQUESTED`, `REOPEN_APPROVED`, `REOPEN_REJECTED`, `REOPEN_CANCELLED`,
`REOPENED`, `ATTACHMENT`, `UPDATED`. Comments are activity rows.

**TaskAttachment**
A file linked to a task and optionally to one activity. Stores the original
`fileName`, the on-disk `storedName`, `mimeType` and `sizeBytes`. 10 MB limit;
JPG/PNG/WebP/PDF only.

**TaskCategory**
A reusable task label (e.g. toll operations, safety). Archived with `active`,
unique by name.

**TaskReopenRequest**
The reopen workflow row: `PENDING` → `APPROVED` / `REJECTED` / `CANCELLED`, with
reason, requester, reviewer, timestamps and an optional review note.

**TaskScopeKind**
The Prisma/PostgreSQL enum behind `Task.scope`: `PROJECT`, `PLAZA`,
`DEPARTMENT`, `HEAD_OFFICE`.

**Toll / Maintenance / Corridor**
The three plaza job families in `PlazaAssignment.role`. Displayed as Toll
Manager, Maintenance Manager and Corridor Manager. They all grant the same
site-manager access; the difference is the job title shown in the picker and
badge.
